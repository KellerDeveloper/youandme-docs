# CLAUDE.md

Гайд для Claude Code при работе в этой папке.

## Что это

Сайт приложения **You&Me** — статические страницы, никакой сборки. Правишь файл,
коммитишь, пушишь — через минуту живое.

Домен — **youandme-app.ru** (куплен 2026-09-01 у timeweb, их же DNS). Хостинг — GitHub
Pages из репозитория `KellerDeveloper/youandme-docs`, ветка `main`. Файл `CNAME` в корне
привязывает домен, трогать его не надо.

Приложение живёт в соседней папке `../YouAndMe` (Xcode, SwiftUI; бэкенд — свой сервер
в Яндекс Облаке, `../YouAndMe/server`). Там свой `CLAUDE.md` со своими правилами —
**здесь они не действуют**: тут нет ни `Metrics.px()`, ни макетов, ни Swift.

## Текущая задача: приём оплаты

Приложение монетизируется **мимо App Store**. Причина: с 1 апреля 2026 Apple не проводит
платежи в России вообще, а российский аккаунт разработчика не имеет права продавать
иностранцам. IAP в этой конфигурации принесёт ровно ноль — не «мало», а ноль.

Поэтому деньги идут так:

```
приложение              этот сайт                    ЮKassa
экран «Премиум»   →  youandme-app.ru       →     форма оплаты
показывает код        вводишь код,                     |
привязки (6 симв.)    выбираешь пакет           вебхук |
      ↑                                                ↓
      |                              Cloud Function в ../YouAndMe/firebase/functions/
      |                                          пишет premiumUntil
      └──────  couples/{id}.premiumUntil  ←───────────┘
```

**Цены (утверждены 2026-09-01):** 129 ₽ / месяц, 299 ₽ / 3 месяца, 899 ₽ / год,
1990 ₽ навсегда. Автосписаний нет — платёж разовый за выбранный срок.

Премиум действует **на пару**: платит один — открывается обоим.

### Что уже сделано

- Лендинг (`index.html`) собран **по макету** `You&Me - Премиум.dc.html` из проекта claude.ai/design
  «YouAndMe приложение» (`52916b2b-373c-4c60-a31e-a6434212d6f1`, читается инструментом
  `DesignSync`). Макет — источник истины: цвета, кегли, отступы и тексты берутся оттуда.
  Страница **тёмная и не подключает `style.css`** — так нарисован макет, а остальной сайт
  светлый. Своя палитра лежит в `:root` внутри самой страницы.
- `offer.html` написан по спеке (макета для оферты нет — это юридический текст).
- `index.html` — ссылки на новые страницы.
- `support.html` — переписан ответ «Does it cost anything?»: там было «no subscriptions,
  no in-app purchases», и это перестало быть правдой. Противоречие между сайтом и офертой
  модерация ЮKassa заметит.

Домен привязан, HTTPS включён (`Enforce HTTPS`), все семь страниц отдаются по
`https://youandme-app.ru`. Экраны премиума в приложении сделаны — `PremiumView.swift`
в `../YouAndMe`, там же поля `premiumUntil` и `payCode` на паре и правила, запрещающие
клиенту их писать. Правила Firestore и Storage **выкачены** 01.09.2026.

### Что не доделано

1. **Форма не платит.** В `index.html` внизу константа `PAY_ENDPOINT = ""`. Пока пусто —
   форма честно пишет «приём оплаты подключается». Заявка в ЮKassa подана 01.09.2026;
   как выдадут ключи, в `../YouAndMe/firebase/functions/` появится функция `createPayment`,
   её адрес встанет сюда, и форма заработает без других правок.
2. **Вебхук ЮKassa не написан** — он и пишет `premiumUntil` после подтверждения платежа.
   Обязан перепроверять платёж запросом к API ЮKassa, а не верить телу уведомления,
   и быть идемпотентным по `payment.id`.
3. **Три URL в App Store Connect** поменять на новый домен: Privacy Policy, Support,
   Account Deletion. Старые адреса GitHub Pages редиректят, так что не сломано.
4. **Скриншот в героя.** Сейчас там рамка-заглушка с подписью «скриншот домашнего экрана
   с фото-виджетом» — нужен настоящий кадр.
5. **Сверить сайт с макетом.** В `You&Me - Премиум.dc.html` появилась секция 3a–3d —
   страницы сайта в тёмном стиле. Сайт переверстан до её появления, глазами не сверялся.

## Правила

- **Plain HTML, никакой сборки.** Ни npm, ни сборщиков, ни фреймворков, ни JS-библиотек.
  Файл → коммит → живое. Так задумано, ломать не надо.
- **Тема одна — тёмная.** Палитра снята с макета премиума и лежит в `:root` в `style.css`.
  Светлой версии нет намеренно: макета под неё не рисовали, а половинчатая вышла бы хуже
  обеих. `prefers-color-scheme` не используем.
- **Общее — в `style.css`:** палитра, шрифты, шапка (`.top`, `.brand`, `.nav-top`), подвал
  (`.foot`), типографика документов (`h1`–`h3`, `p`, списки, `.card`, `.updated`, таблицы).
  Правишь шапку или подвал — правь там, они одинаковые на всех семи страницах.
- **`index.html` подключает `style.css` и добавляет свой `<style>`** — только то, что нужно
  лендингу: герой, карточки функций, шаги, клетки кода, тарифы, кнопки оплаты, вопросы.
  Общие вещи туда не дублировать.
- **Шапка одинакова везде,** и её якоря абсолютные (`/#ceny`, `/#voprosy`) — со страницы
  документа они ведут на главную к нужному месту. Относительные `#ceny` там вели бы в никуда.
- **Внешних загрузок нет вообще.** Шрифты макета (Onest, Manrope, IBM Plex Mono, Material
  Symbols) лежат в `fonts/` и подключены в `style.css`. С 16.10.2026: Google Fonts отдавал
  Google IP каждого посетителя, а политика говорит, что трансграничной передачи нет.
  Иконок Material Symbols в наборе только восемь — новая иконка требует перекачать набор
  (как — в комментарии в `style.css`). CDN, счётчики, виджеты не добавлять.
- **Логотип — знак 21b из макета «Логотип»**, как `LogoMark.swift` в приложении: SVG
  `.brand-mark` в шапке всех страниц (с 16.10.2026, раньше — два кружка и слово).
  `favicon.png` (64, кадр плотнее) и `apple-touch-icon.png` (180, целиком) сделаны `sips`
  из иконки приложения `YouAndMe/Assets.xcassets/AppIcon.appiconset/logo-21b-dark-1024.png`.
  Поменяется иконка — пересобрать оба файла из неё, а не рисовать заново.
- **Тон текстов человеческий** — на главной, в `support.html`, `delete-account.html`:
  спокойно, по делу, без маркетингового ора.
- **Политика и согласие — тексты юриста, слово в слово** (с 16.10.2026, исходники —
  «01. Политика…» и «02. Согласие…» ИП Келлер). Своими словами их не дописывать и не
  «очеловечивать»: любая правка — через юриста. Английские версии — пункт-в-пункт перевод.
- **Требования юриста к сайту (инструкция для РКН, 16.10.2026):** в подвале полное имя ИП,
  ИНН, ОГРНИП, Email и ссылки на политику и согласие; у каждой формы с ПДн (оплата, донат)
  галочка, по умолчанию снятая, без неё кнопки неактивны; баннер cookie при первом заходе.
  Политики cookie и согласия на рассылку **пока нет** — юрист текстов не дал; придут —
  страницы в подвал, cookie — ещё и вторая ссылка в `cookie.js`. Фразу «сайт не является
  публичной офертой» из инструкции **не ставить**: у нас есть оферта, фраза ей противоречит.
- **Русские страницы — для российской аудитории, английские — для App Store.** Лендинг
  и оферта только на русском: аудитория почти вся из России.
- **Дату в `.updated` менять при каждой правке содержания.**
- **Политика и согласие — юридические документы, и редакция в них не декоративная.**
  Сейчас редакция 4, от 16.10.2026. **С iOS и Android 1.7 номер ставится на сервере**,
  без релиза: строка `consent_version` в общих флагах (`POST /admin/sections`
  `{"section":"consent_version","backend":"5"}`), приложения и веб берут большее из неё
  и вшитого числа (`Constants.consentVersion`, `CONSENT_VERSION`). Порядок: **сначала
  новый текст сюда и пуш, потом номер на сервер** — иначе человек согласится с текстом,
  которого ещё нет. Сборки до 1.7 видят только вшитое число. Редакция 3 так и не доехала
  до приложений — ровно от этого флаг и спасает. Перечень данных в трёх
  плашках на экране согласия (`ConsentTexts.storedData`) тоже обязан не противоречить
  пункту 2 `consent-ru.html`.
- **Место хранения данных — Россия, Яндекс Облако** (YDB, Object Storage, Cloud Functions +
  API Gateway, Postbox), зона `ru-central1`. Firebase остался только транспортом пушей
  для Android. Писать в документах «данные на серверах Google» больше нельзя — это было
  правдой до сентября 2026.
- **Оферта — юридический документ.** Правки в `offer.html` (особенно цены в разделе 5
  и возвраты в разделе 6) должны совпадать с тем, что написано на главной.
  Разошлись — это претензия от покупателя, а не опечатка.

## Про оплату внутри приложения — не предлагать

Периодически возникает идея встроить платёжную форму прямо в iOS-приложение (например,
через ЮKassa iOS SDK). **Это решённый вопрос: не делаем.**

Правило Apple 3.1.1 требует продавать цифровой функционал внутри приложения только через
IAP. Правило 3.1.5 разрешает сторонние платежи, но лишь за то, что потребляется **вне**
приложения (такси, доставка, билеты) — именно поэтому SDK ЮKassa вообще живёт в App Store.
Премиум-функции это первый случай, а не второй. Платёжная форма внутри приложения —
очевидное и наглядное нарушение, ревьюер видит его сразу.

Принятый компромисс: в приложении только статус премиума и код привязки, **без цен
и без кнопок покупки**. Оплата здесь, на сайте.

Адрес сайта на экране премиума **кликабельный, но только у связанной пары** — решение
владельца от 01.09.2026. Кликабельность это ровно то, что правило 3.1.1 называет
anti-steering, поэтому в соло-режиме адрес остаётся простым текстом: ревью App Store
проверяет приложение одним аккаунтом и пару не заводит, то есть видит именно соло.
Понадобится откатить совсем — правится метод `siteLine` в `PremiumView.swift`, текст
остаётся, исчезает только разметка ссылки.

## Git

- Ветка `main`, пуш в `main` = деплой. Промежуточной среды нет.
- **СТОП на ревью перед коммитом.** Правишь → показываешь владельцу что и почему →
  ждёшь явного «ок» → только потом коммит. Сайт публичный и деплоится сразу.
- Коммит — через глобальный скилл `commit`, не руками.
